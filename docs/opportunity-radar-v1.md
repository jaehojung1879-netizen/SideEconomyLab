# 기회 탐색 v1 — 관측에서 다음 검증으로

기회 탐색은 기존 지도 작업공간의 첫 화면입니다. 시장 변화를 읽고 지역 연구와 사업성 검토로 이동합니다. 매출 전망·투자 승인·종합 수익 점수를 생성하지 않습니다. 기존 7개 후보의 점수·검증 게이트·승격 판단과 개인 저장본은 그대로 유지합니다.

## 실제 확인한 데이터

2026-10-09 GitHub Actions에서 기존 `SEOUL` 서버 비밀값으로 수집했습니다. [인증 수집·재현 검사](https://github.com/jaehojung1879-netizen/SideEconomyLab/actions/runs/37908347723).

| 출처 | 실제 관측 | 보존 행 | 범위 |
|---|---|---:|---|
| [추정매출 OA-15572](https://data.seoul.go.kr/dataList/OA-15572/A/1/datasetView.do) | 2025 Q2~2026 Q2, 5개 분기 | 513 | 3001492 / 3120189, 원·건 |
| [점포 OA-15577](https://data.seoul.go.kr/dataList/OA-15577/A/1/datasetView.do) | 동일 5개 분기 | 929 | 같은 공식 코드, 전체·일반·프랜차이즈·분기 개폐업 |

현재 두 출처에 걸친 186개 지역·업종 조합 중 85개는 일부 관측이 없습니다. 부재는 0으로 채우지 않습니다. 이 범위는 명동·남대문 관광특구와 강남역의 목적 표본이며 서울 전체의 시장 상태를 대표하지 않습니다. 최신 공통 관측은 2026 Q2입니다. 수집 시각, 관측 분기, 공식 페이지 갱신일은 별개이고 실제 공표일은 UNKNOWN입니다. 갱신주기 메타정보가 연간이라고 표시되는 점포 페이지와 실제 분기 필드는 구별합니다.

매출 API는 **분기 인자만** 지원합니다. 5개 분기의 전체 페이지 106,626행을 순차 검사하고 지정 코드만 보존했습니다. 점포 API는 공식 지역 인자를 사용합니다. 124회 요청, 최대 260회 예산, 응답 4MB/분기 매출 60,000행 제한, 최대 2회 제한 재시도입니다. 초기 지역 인자를 매출에도 붙인 실행은 행 예산 초과로 실패했고 이전 자료를 보존했습니다. 공식 명세 확인 후 수정했습니다. 해당 실패를 숨기지 않습니다.

선택 행의 명세상 필드·수치를 불변 gzip 스냅샷에 보존합니다. 관련 없는 서울 전체 행과 불필요한 성·연령별 매출 필드는 저장하지 않습니다. 전체 검사 페이지의 행수·SHA-256 수신 내용 해시는 보존하지만 관련 없는 행을 재다운로드 없이 재현할 수 있다는 의미는 아닙니다. 원본 응답의 모든 열을 보존하는 수집기는 아닙니다.

## 지리·시간의 하드 게이트

[공식 변경 공지](https://data.seoul.go.kr/together/notice/datasetNoticeView.do?bbsCd=10008&ditcCd=&pageIndex=1&seq=a2197dabd5a3a52edd6fe0d4eead6bd3)는 2024년 표준단위구역 전환과 2026-07-03 이후 매출 이력 제공 기준 변경을 알립니다. [상권 정의](https://golmok.seoul.go.kr/introduce3.do)는 2022년 표준단위구역에 기반한 영역 재설정을 설명합니다. 이것만으로 **2025 Q2~2026 Q2 경계가 동일하다거나 기존 지도 1,650개 중심점과 동등함을 입증하지 않습니다.**

분기별 경계 버전, 새 영역의 CRS, 공식 대응표를 검증하지 못했습니다. `config/opportunity-radar-v1.json`의 지리 비교 확인은 false, 버전·CRS·geometry version·crosswalk는 null입니다. **실제 비교 신호 0건, 새 지도 레이어 비활성.** 코드·이름이 같거나 중심점이 가까워도 연결하지 않습니다. 지도는 기존 수요 기준이고 새 관측은 별도의 출처 기준 분석입니다. 지도 선택은 기존 지역 연구로 연결되며 새 통계 선택은 지도 위치를 옮기지 않습니다.

[250m 생활인구](https://data.seoul.go.kr/dataList/OA-22784/A/1/datasetView.do)와 [전환 공지](https://data.seoul.go.kr/together/notice/boardView.do?seq=721010a1522630fbf7a78d381a8326ee)를 검토했습니다. 새 격자·CRS·대응표·관측 정의 미검증으로 활동 신호를 보류합니다. 분기 인구를 91로 나눠 관측 일유동으로 사용하지 않습니다.

## 검증 후 열릴 계산

검증된 지리 버전·경계 버전·CRS와 공식 근거 URL, 같은 공식 지역·생활밀접 업종, 5개 연속 분기, 필수 수치 완결성, 신원 일관성, 최신 분기 종료 후 180일 이내 조건이 모두 필요합니다. 신호는 공개 추정통계에서 계산한 연구 신호이며 실측 현장 증거가 아닙니다.

- 소비·점포 변화: 전년 같은 분기 대비 `(현재/기준−1)×100`. 기준 0이면 증가율 미계산. 소비가 증가하고 점포 증가율을 웃돌 때만 기술합니다. 명목 가격·카드 보정·대형점 집중은 대안 설명입니다. 시장 공백이나 수익으로 단정하지 않습니다.
- 개폐업 흐름: 최근 3개 연속 분기에 진입·퇴출이 관측되면 순증 방향이 계속 양수/음수인지, 방향이 혼재하는지 기술합니다. 통계적 이상탐지나 원인 추정은 아닙니다. 이전·업종 전환·등록 시차를 확인해야 합니다.
- 활동 변화: 비활성. 추가 유효 출처를 연결하기 전까지 계산하지 않습니다.

신호마다 실제 기준·현재값, 비교 기간, 출처 ID, 완결성, 대안 설명, 다음 행동을 남깁니다. 소비/점포 수치 정렬은 동일 업종을 선택해야 합니다. 서로 다른 업종을 종합점수로 순위화하지 않습니다.

## 사용 흐름과 근거 구별

1. 첫 화면: 범위·관측 신선도·비교 통과 건수·기존 가설. 자료 없음/비교 보류를 명시합니다.
2. 조건 선택: 출처 지역, 업종, 분기, 신호, 근거 상태. 목록에서 개별 관측을 선택하면 필요한 숫자와 검증 행동을 읽습니다.
3. 상세: 소비·점포/활동 추이, 관련 사업 가설, 위험·불확실성. 충분한 비교 가능 관측이 있을 때만 선형 시계열을 그립니다. 현재 실자료에는 추세선을 그리지 않습니다.
4. 출처·기준일·방법은 펼쳐 확인합니다. 공식 추정통계 / 파생 연구 신호 / 기획 가정 / 미확인 / 현장 근거를 구별합니다.
5. 기존 지도 선택과 사업 가설을 유지해 사업성 검토로 이동합니다. 새 통계의 지역 대응이 미확인임을 명시하며, 통계값을 수익 가정에 넣거나 개인 사이트를 자동 생성하지 않습니다.

새 가설의 [연구 전용 구조](data/opportunity-hypothesis.schema.json)는 고객, 관측 변화, 문제, 사업 메커니즘, 운영 방식, 자본·시간 가정, 대안, 부족한 근거, 최소 검증을 구별합니다. 이번에는 적격 신호가 없어 가설을 생성하지 않았습니다. 향후 작성 시 참조 신호의 실재·적격성 및 자본 범위를 별도 확인해야 하며, 구조 적합성은 사업 승인 근거가 아닙니다.

## 재현·성능·실패 보존

```sh
python pipeline/opportunity_radar.py --check
python -m unittest discover -s tests -p test_opportunity_radar.py -v
```

새 수집은 GitHub Actions **Seoul Open Data API smoke**의 `radar_history=true`로 실행합니다. 기존 smoke 경로는 유지됩니다. *(v2에서 대체됨: 수집은 전용 수동 워크플로 **Opportunity Radar official collection**이 맡고 smoke 워크플로에서 `radar_history`를 제거했습니다. [v2 문서](opportunity-radar-v2.md) 참고.)* 수집 결과는 artifact만 만들고 원격 main에 쓰지 않습니다. 전체 검증 후 정적 묶음을 검토·커밋합니다. 서버 로그에는 키/응답 메시지/인증 URL을 출력하지 않습니다. 기존 HTTP :8088 공식 엔드포인트를 사용하므로 제공자의 암호화 전송 지원 확인은 남아 있습니다.

필수 스키마·숫자·기간·키·범위·페이지·점포 항등식을 검사합니다. 불변 스냅샷과 정확한 결정적 파생, 세부 파일 해시를 검사하고 실패 시 이전 묶음을 복원합니다. 별도 최근 수집 상태는 실패를 표시해 오래된 성공을 새 성공으로 위장하지 않습니다. 서버는 raw를 처리하고 브라우저에는 111,773바이트 요약과 선택한 작은 상세 파일만 전달합니다. 지도 조작·후보 변경은 원천 API나 raw 스냅샷 다운로드를 일으키지 않습니다. 약 13.8MB 기존 판단 자료는 **사업성 검토를 열 때** 지연 로딩합니다.

기본 지도 표시는 기존 수요 상위 12개 중심점입니다. 지역 분석에 들어가면 기존 전체 탐색·공급/사분면·현장·개인 기록 기능을 사용할 수 있습니다. Kakao 설정과 지도 어댑터는 변경하지 않았습니다. 실제 Kakao 도메인 허용·JavaScript 키 승인은 계정 측 검증으로 남습니다.

## 범위 밖

서울 전체 자료 통합, ML/수익 점수, 승인 자동화, DB/서버/유료 인프라, 구매·리스·파일럿은 이번 범위에 없습니다. v2는 데이터 수를 늘리기 전에 **공식 버전 있는 경계/대응표와 같은 분기 업종 정의**를 검증하는 것이 우선입니다.
