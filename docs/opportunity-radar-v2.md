### 실제 데이터 사례 3건

기준 분기 2025Q2 → 2026Q2(전년 같은 분기), 명목 금액입니다. 원인이나 수익을 추정하지 않으며 해석은 "다른 설명"에 적은 확인을 거쳐야 합니다.

1. **용산구 · 컴퓨터및주변장치판매 — 소비·점포 동반 감소.** 추정 소비 약 4,475억원 → 3,726억원(−16.74%), 점포 2,349개 → 2,232개(−4.98%). 최근 4개 분기 모두 폐업이 개업보다 많았고(분기 폐업 27~42, 개업 1~8, 순 −109개), 소비는 2025Q4(약 5,164억원)를 정점으로 줄었습니다. *다른 설명:* 재개발·상가 철거, 업종 분류 변경, 대형 점포 폐점. *다음 확인:* 폐업 점포의 위치와 사유.
2. **송파구 · 슈퍼마켓 — 소비 감소·점포 증가.** 추정 소비 약 924억원 → 866억원(−6.23%)인데 점포는 687개 → 725개(+5.53%), 4개 분기 순개업 +36개. 소비는 2026Q1 저점 이후 직전 분기 대비 +3.05%로 반등했습니다. *다른 설명:* 신규 점포 매출의 집계 시차, 소규모·무인 점포 증가, 업종 분류 변화. *다음 확인:* 최근 개업 점포의 실제 영업 상태와 상권 내 중복 입점.
3. **동대문구 · 청과상 — 소비 증가·점포 정체이지만 최근에는 둔화.** 추정 소비 약 6,589억원 → 7,712억원(+17.05%), 점포는 900개 → 901개(+0.11%). 다만 증가는 2025Q3의 한 번의 도약(약 8,188억원)에서 나왔고 이후 세 분기 연속 감소했습니다(직전 분기 대비 −3.42%). 전년 같은 분기 비교만 보면 보이지 않는 모습이라 차트의 분기별 추이를 함께 확인해야 합니다. *다른 설명:* 가격 상승, 특정 대형점의 결제 집중. *다음 확인:* 주요 점포 몇 곳의 매출 분포와 가격 변화.

이 사례는 모두 "무엇이 변했는가"를 보여줄 뿐 미충족 수요·진입 기회의 증거가 아닙니다.


## 두 개의 지리 관문 — 서로 독립

| 출처 지리 | ① 분기 비교 (같은 지리·업종을 분기 사이에 비교해도 되는가) | ② 기존 지도 연결 (1,650개 상권 지도에 붙여도 되는가) |
|---|---|---|
| 자치구 공식 집계 (OA-22176 / OA-22173) | **통과** → 변화율·개폐업·발견 활성 | **미통과** → 출처 기준 목록·차트로만 표시 |
| 상권 표본 v1 (OA-15572 / OA-15577, 2곳) | **미통과** → 관측값만 표시, 변화 비교·추세선 없음 | **미통과** → 지도 연결 없음 |

①이 통과해도 ②가 자동으로 열리지 않고, ②가 막혀도 ①로 검증된 출처 기준 변화는 보여줍니다. 파이프라인(`pipeline/opportunity_radar.py --check`)과 브라우저 모두 이 독립성을 강제합니다. ①이 미통과인 출처에서 변화값이 하나라도 나오면 검사가 실패하고, ②가 미통과인 출처에 지도 연결값이 있으면 실패합니다.

### ① 자치구 분기 비교 — 근거

2026-10-10 GitHub Actions에서 기존 `SEOUL` 서버 비밀값으로 공식 페이지·API를 직접 조사했습니다([조사 기록](../research/opportunity-radar-v2/geography-probe.json), 838회 요청).

- **공식 정의:** [추정매출-자치구](https://data.seoul.go.kr/dataList/OA-22176/S/1/datasetView.do)·[점포-자치구](https://data.seoul.go.kr/dataList/OA-22173/S/1/datasetView.do)는 자치구별 집계(단위 원, 전체 점포 = 일반 + 프랜차이즈)이며 행정안전부 주민등록 행정기관코드를 씁니다.
- **제공 기준:** [제공기간 변경 공지](https://data.seoul.go.kr/together/notice/datasetNoticeView.do?bbsCd=10008&ditcCd=&pageIndex=1&seq=a2197dabd5a3a52edd6fe0d4eead6bd3)(2026-06-19, 적용 2026-07-03)는 2024년 공간 단위가 표준단위구역으로 바뀌었고, **데이터 일관성을 위해 표준단위구역 기준 매출이 있는 2021년 이후 자료만 제공**한다고 밝힙니다.
- **코드·이름 불변:** 두 API의 전체 이력(2021Q1~2026Q2, 22개 분기)에서 자치구 코드 25개와 이름이 1:1로 고정입니다. 업종 코드↔이름도 고정입니다(매출 63개, 점포 100개 업종).
- **하위 행정구역 불변:** [추정매출-행정동](https://data.seoul.go.kr/dataList/OA-22175/S/1/datasetView.do)·[점포-행정동](https://data.seoul.go.kr/dataList/OA-22172/S/1/datasetView.do)의 행정동 425곳(25개 구 전체) 코드·이름 집합이 2025Q2~2026Q2 다섯 분기 모두 동일합니다. 비교 기간 중 행정동 분할·통합·재코딩이 없었습니다.
- **남은 한계:** 행정표준코드 API는 이 저장소 인증 범위 밖(HTTP 403)이라 조회하지 못했습니다. 자치구 사이 미세 경계조정 여부는 공식 경계 이력으로 확인하지 않았습니다. 금액은 물가를 보정하지 않은 명목값입니다.

### ① 상권 분기 비교 — 미통과 이유

코드·이름은 안정적입니다. 5개 분기 매출 응답의 상권 코드 1,579개는 모두 현재 공식 영역 목록에 있고 이름 변경은 없습니다. 그러나 다섯 분기 모두 등장하는 코드는 1,555개로 분기마다 구성이 달라집니다. 공지는 매출이 2021년 이후 표준단위구역 기준이라는 점까지만 말합니다. 상권 영역([OA-15560](https://data.seoul.go.kr/dataList/OA-15560/S/1/datasetView.do))은 비정기 갱신이고 분기별 영역 버전이나 과거 분기 재계산 여부가 공개되지 않았습니다. **같은 코드·이름만으로는 비교 근거가 아니므로** 상권 변화 비교는 계속 보류합니다.

### ② 기존 지도 연결 — 미통과 이유

- 기존 GIS 1,650개 상권은 현재 공식 영역 API(`TbgisTrdarRelm`)와 **코드·중심 좌표(EPSG:5181)·이름이 1,650개 모두 일치**합니다. 기존 지도가 공식 목록에서 만들어졌다는 확인입니다.
- 그러나 중심점 일치는 도형(경계) 일치가 아닙니다. 영역 도형 버전, 분기별 대응표, 변경 이력이 없어 새 통계를 지도에 붙이지 않습니다. 이름이나 가까운 중심점으로 핀을 옮기지 않습니다.
- 자치구 경계 도형은 이번에 수집하지 않았습니다. 자치구 결과는 지도 대신 **출처 기준 화면**(순위 막대·추이 차트)으로 보여줍니다.

## 계산 규칙

| 항목 | 규칙 |
|---|---|
| 변화율 | `(비교값 ÷ 기준값 − 1) × 100`, 소수 둘째 자리 |
| 기준값 0 | UNKNOWN (변화율 없음, 차이는 표시) |
| 관측 누락 | UNKNOWN (0으로 채우지 않음) |
| 비교 관문 미통과·이름/코드 변경·오래된 관측(분기 종료 후 180일 초과) | BLOCKED |
| 전년 같은 분기 | 2025Q2 → 2026Q2 (발견 분류는 이것만 사용) |
| 직전 분기 | 2026Q1 → 2026Q2 (계절 영향 포함, 참고용) |
| 개폐업 흐름 | 최근 4개 분기 순개업(개업 − 폐업)이 모두 양수 = 계속 증가, 모두 음수 = 계속 감소, 나머지 = 혼재 |
| 소비·점포 패턴 | 소비 ±5%, 점포 ±3%를 의미 있는 변화 폭으로 사용 |
| 발견 목록 대상 | 기준 분기 소비 1억원 이상 **그리고** 점포 10개 이상, 패턴이 4개 유형 중 하나이거나 개폐업 방향이 지속 |

4개 패턴: **소비 증가·점포 정체/감소**, **소비 감소·점포 증가**, **소비·점포 동반 증가**, **소비·점포 동반 감소**. 이 패턴들은 시장 모습을 설명할 뿐이며 미충족 수요나 수익성의 증거가 아닙니다. 패턴마다 왜 볼 만한지, 다른 설명, 다음 확인을 함께 둡니다. 정렬은 소비 변화율·점포 변화율·지역 이름 같은 단일 지표만 쓰고 종합 점수는 없습니다. 원 단위 금액을 업종끼리 비교하지 않습니다(같은 지역 안 업종 비교는 변화율만 사용).

밴드(±5%/±3%)와 규모 기준(1억원·10개)은 판단을 위한 연구 기준이며 `config/opportunity-radar-v2.json`에 공개되어 있습니다. 바꾸면 결과도 결정적으로 다시 계산됩니다.

## 화면

- **지역 · 업종 · 비교 기간** 선택. 첫 화면은 기준 분기 소비가 가장 큰 업종의 25개 자치구 비교입니다(중립 기본값).
- **요약 카드**: 추정 소비 변화율·전후 금액(억원/만원/원 자동 단위, 반올림 시 "약")·차이, 점포 변화율·전후 개수·최근 분기 개폐업·4개 분기 순개업.
- **추이 차트**: 소비와 점포를 같은 축에 원값으로 그리지 않습니다. 기준 분기 = 100 지수로 맞추고, 점을 가리키거나 누르면 원래 값(원 단위 전체)이 보입니다. 아래 표에 반올림 없는 원값이 있습니다.
- **조사할 발견**: 어디·업종·무엇이 변했는지·수치·비교 기간·왜 볼 만한지·다른 설명·다음 확인. 누르면 해당 시장 화면으로 이동합니다.
- **관문 설명**: "분기 비교 가능 / 지도 연결 안 함" 배지와 이유·공식 근거 링크.
- 모바일(390px): 시장 변화 / 조사할 발견 전환, 큰 선택 상자, 화면 폭에 맞춘 차트, 가로 넘침 없음.
- **사업성 검토**로 이동해도 지도 선택·사업 가설·개인 저장본은 그대로이며, 통계 금액을 매출 전망에 자동 입력하지 않습니다.

## 재현·실패 보존·성능

```sh
python pipeline/opportunity_radar.py --check          # 불변 스냅샷 → 요약·상세를 바이트 단위로 재현
python -m unittest tests/test_opportunity_radar.py -v
node tests/radar-models.cjs                           # 브라우저 계산 = 파이프라인 계산 (전 항목)
python pipeline/radar_preservation.py                 # 기존 증거 파일 바이트 보존 확인
```

- 수집: **Opportunity Radar official collection** 워크플로(`mode=collect`). 자치구 API는 분기 인자를 무시하고 전체 이력을 돌려주므로(조사: 인자 유무와 무관하게 같은 건수) 전체 이력을 한 번 끝까지 페이지 검사하고 비교 5개 분기만 보존합니다. 페이지 건수·해시, 분기별 행·지역·업종 수, 코드↔이름 불변 여부를 스냅샷에 기록합니다.
- 실패 시: 이전에 검증한 묶음을 그대로 두고 상태 파일만 `BLOCKED`(사유 코드)로 바꿉니다. 첫 실수집 시도는 분기 인자 무시 때문에 행 예산을 넘었고 **아무것도 게시하지 않고 실패**했습니다([실행](https://github.com/jaehojung1879-netizen/SideEconomyLab/actions/runs/38020401407)).
- 브라우저는 작은 요약(열 배열 형식)만 먼저 받고, 지역을 고르면 그 지역의 상세 파일 하나를 해시 검증 후 불러옵니다. 원천 API·원자료 스냅샷·13.8MB 판단 자료는 첫 화면에서 받지 않습니다.

## 범위 밖과 다음 단계

행정동 자료(425곳)는 식별자 안정성까지 확인했지만 이번에는 수집·게시하지 않았습니다. 250m·관광·행사·부동산·이동 자료는 다루지 않습니다. 다음 우선순위는 아래 v3 항목을 보세요.

## 성능

| 파일 | 크기 | 언제 받는가 |
|---|---:|---|
| `opportunity-radar.json` 요약 색인 | 522,991 B (gzip 약 102 KB) | 첫 화면 |
| `opportunity-radar-details/<구>.json` 27개 | 개별 최대 68,582 B, 합계 1.8 MB | 지역·업종을 고를 때 한 파일씩, 해시 검증 |
| 원천 스냅샷 `data/opportunity-radar/*/source.json.gz` | `docs/` 밖에 보관 · 배포·브라우저 미사용 | 받지 않음 |
| `decision-evidence.json` | 약 13.8 MB | 사업성 검토를 열 때만 |

요약 색인은 열 배열 형식이며 v1(111,773 B)보다 큽니다. 서울 25개 자치구 × 업종 2,683개 조합을 담기 때문입니다. 행정동(약 4만 조합)을 더하려면 색인 분할이 필요합니다.

## v3 우선순위

1. **자치구 경계 도형(관문 ②)**: 공식 자치구 경계의 버전·CRS를 확인해 자치구를 지도 레이어로 표시. 핀 이동 없이 폴리곤으로만 연결.
2. **긴 이력으로 지속성 검증**: 자치구 API는 2021Q1부터 22개 분기를 제공합니다. 5분기가 아니라 다년 이력으로 같은 분기 비교를 반복해, 한 번의 도약(예: 동대문구 청과상)과 지속 추세를 구분.
3. **행정동 425곳**: 코드·이름 안정성은 확인했습니다. 행정표준코드 API(DATA_GO 구독 범위)로 행정동 변경 이력을 확인한 뒤 수집하고, 색인을 구별 파일로 분할.
4. **상권 관문 ①**: 서울신용보증재단에 분기별 상권 영역 버전과 재계산 여부를 확인하고, OA-15560 영역 도형을 수집해 1,650개 지도와 도형 단위로 대응.
5. **급변 38건 원인 분류**: 점포 배정·업종 분류·결제 처리 변경인지 원자료로 판별.
6. **물가 보정**: 소비자물가와 업종 가격 지수를 연결해 명목 금액의 한계를 줄이기.
7. **현장 검증**: 발견 중 소수를 골라 점포 관찰·고객 인터뷰. 확인된 것만 `data/opportunity-hypothesis.schema.json`에 가설로 기록.
